# 시스템 구조

## 기술 스택

| 영역 | 사용 기술 |
| --- | --- |
| 프레임워크 | Next.js 14 (App Router), TypeScript |
| 스타일 | 순수 CSS (globals.css, CSS 변수). 그리드는 AG Grid |
| 데이터 조회 | SWR (revalidateOnFocus + 5초 dedup) |
| 인증 | NextAuth v5, 구글 OAuth (@pusan.ac.kr 도메인 제한) |
| DB / ORM | PostgreSQL 17 (서버 자체호스팅, Docker) + Prisma |
| 배포 | 서버실 PC Docker. CI 가 구운 GHCR 이미지를 SHA 태그로 pull |
| HTTPS | Caddy (80/443 수신, Let's Encrypt 자동 갱신) |
| 엑셀 파싱 | adm-zip 으로 OOXML 직접 파싱 (일반 라이브러리가 이 실적 파일을 못 읽어서) |

## 전체 구조

```
[사용자 브라우저]
      │ https://aicms.pusan.ac.kr  (구글 로그인 @pusan.ac.kr)
      ▼
[Caddy]  80/443, Let's Encrypt 인증서
      │ reverse_proxy localhost:3000
      ▼
[app 컨테이너]  cms_app, Next.js, 127.0.0.1:3000 만 바인딩
      │ docker 네트워크 (db:5432)
      ▼
[db 컨테이너]  cms_db, postgres:17, 볼륨 cms_pgdata
```

- 앱은 `127.0.0.1:3000` 에만 바인딩한다. 외부에서 평문 3000 으로 직접 못 들어온다. 반드시 Caddy 를 거친다.
- DB 도 `127.0.0.1:5432` 에만 바인딩한다. 외부 노출 없음. DataGrip 같은 툴은 SSH 터널로 붙는다.
- 데이터는 `cms_pgdata` 도커 볼륨에 남는다. 컨테이너를 갈아끼워도 데이터는 유지된다.

## 엑셀 파싱이 왜 직접 구현인가

실적 엑셀이 모든 XML 태그에 `x:` 네임스페이스 접두사를 달고 저장된다. exceljs·SheetJS·openpyxl 이 전부 워크시트를 못 읽는다. 그래서 `src/lib/records-xlsx.ts` 에서 adm-zip 으로 압축을 풀고 접두사를 벗겨낸 뒤 직접 파싱한다. 큰 숫자(학번)가 과학적표기(`2.02213511E8`)로 저장되는 것도 여기서 평문 복원한다.

## 권한 체계 (RBAC)

DB 기반 3단계 역할. 구글 로그인하면 `AppUser` 테이블에 자동 등록된다.

| 역할 | 권한 |
| --- | --- |
| 일반(GENERAL) | 신규 로그인 기본값. 대시보드 요약만 열람 |
| 관리자(ADMIN) | 기업·학생 등 데이터 전체 열람·수정 |
| 슈퍼관리자(SUPER) | 위 + 사용자 권한 관리(/admin/users) |

- 로그인 자체는 @pusan.ac.kr 이면 누구나 된다. 막는 건 로그인이 아니라 **역할**이다.
- 최초 슈퍼관리자는 환경변수 `SUPER_ADMIN_EMAILS` 로 지정(부트스트랩). 현재 값은 octopus121@pusan.ac.kr.
- 권한 변경은 슈퍼관리자가 화면(/admin/users)에서 수행. 변경은 재로그인 없이 즉시 반영(매 요청 DB 조회).
- 권한 검사: 서버 `requireRole` 이 진짜 보안 경계다. 화면 쪽 메뉴 숨김(`RoleGuard`)은 사용성용일 뿐 보안이 아니다.
- API 라우트 31개 전부에 권한 검사가 걸려 있다. 대시보드·연도별 현황판만 `requireUser`(로그인만), 사용자 관리만 `SUPER`, 나머지는 `ADMIN`.

## 데이터 모델 (주요 테이블)

| 테이블 | 설명 |
| --- | --- |
| Company | 기업 기본정보 |
| Collaboration | 기업 협업정보(1:1, 인턴십/취업/산학 가능 여부 등) |
| ContactPerson | 기업 실무자 |
| ContactHistory | 기업 컨택 이력 |
| Project | 산학협력 프로젝트 |
| ProjectStudent | 프로젝트-학생 연결 |
| Lab | 연구실(지도교수) |
| Division | 분과 참조 |
| Internship | 인턴십 |
| InternshipStudent | 인턴십-학생 연결 |
| Student | 학생(학번 기준, 실명+마스킹명) |
| Counseling | 진로지도 상담 |
| StudentInternship | 학생별 수동 입력 인턴십 |
| YearStat | 연도별 정량실적 현황판 값(엑셀 전체현황 시트 기반) |
| SwcuYear / SwcuIndicator / SwcuRaw | SW중심대학 성과지표(연차·지표·원시집계) |
| AppUser | 사용자/권한(RBAC) |
| UploadedFile | 업로드한 실적 엑셀 원본 보관(재다운로드용, kind 별 최신 1건) |
| DartCorpCode | DART 회사코드 캐시(자동조회용, 약 118,000건) |
| Counter | 사람이 읽는 코드(C-001 / P-0001 / H-0001) 채번 |

동시 편집 대비로 Company·ContactPerson·ContactHistory 등은 `version` 낙관적 락을 쓴다. 다른 사람이 먼저 저장했으면 409 로 막고 새로고침을 요구한다. 삭제는 기본적으로 `isActive=false` soft delete 다.

## 브랜치 전략 (Git Flow)

- `feature/*` 에서 작업 → `develop` 으로 머지(보통 squash)
- `develop` → `main` 으로 릴리스(merge commit). main 에 들어가면 CI 가 새 GHCR 이미지를 굽는다.
- 운영 긴급 수정은 `hotfix/*` 를 `main` 에서 분기 → main·develop 양쪽에 머지(merge commit, 같은 커밋 공유)
- **이미지가 구워지는 것과 서버에 올라가는 것은 별개다.** 실제 배포는 사람이 서버에서 `./deploy.sh` 를 돌려야 일어난다.
